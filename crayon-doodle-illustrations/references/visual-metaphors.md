# 视觉隐喻方法

## 核心原则

不要先问“画什么行业图标”，先问：**这个观点在物理世界里像什么？**

把抽象关系翻译成一个可以被看见、被操作、被阻塞、被连接、被运输、被测量的场景。

## 常用隐喻家族

### 1. 路径 / 桥 / 河

适合：

- 从 A 到 B 的转化
- 过渡成本
- 中间断点
- 用户旅程
- 认知跨越

变化方式：桥可以断、变窄、收费、分叉、被水淹；河可以变成涓流或暴雨。

### 2. 水 / 龙头 / 管道

适合：

- 收入
- 流量
- 留存
- 复购
- 稳定供给

重点不是“画个水管”，而是让流量状态可见：滴水、喷涌、漏水、蓄水、回流。

### 3. 机器 / 自制装置

适合：

- 产品系统
- AI 工作流
- 自动化
- 软件 + 服务 + 硬件
- 多环节协作

机器要有手工感：螺丝、风扇、线缆、灯泡、仪表，而不是高科技机柜。

### 4. 容器 / 盒子 / 瓶子

适合：

- 产品边界
- 用户池
- 收费模式
- 知识沉淀
- 资产积累

可以通过“装得下 / 漏出去 / 越积越多 / 被分装”表达差异。

### 5. 动物 / 植物

适合：

- outlier
- 生态
- 生长
- 适应性
- 群体共识与异类

不要画成儿童绘本。动物应像“观点角色”，有明确功能，不卖萌。

### 6. 工具 / 绳子 / 电线

适合：

- 协作
- 连接
- 执行
- 反馈回路
- 工具链

线可以贯穿整页，成为视觉导向。

### 7. 钱 / 订单 / 信封 / 包裹

适合：

- 销售
- 付费
- 交付
- 商业闭环
- 现金流

尽量用动作表达，例如“钱从哪边流回来”，而不是堆货币符号。

## 设计步骤

每页按下面顺序想：

1. 这页的抽象关系是什么？
2. 哪个物理系统最像这个关系？
3. 这个系统最关键的“动作”是什么？
4. 哪个瞬间最适合画？
5. 哪些辅助元素可以删掉？

## 原创规则

同一个概念至少尝试 3 个隐喻，再选最清楚的。

例如“产品不等于销售”：

- 方案 A：一台机器只能亮屏，但没有收款口
- 方案 B：一座桥只修到河中央
- 方案 C：餐厅只把菜做好，没有菜单、服务员和结账台

最后选择最符合文章语境的一种。

## 禁止偷懒

- 不要一提增长就画上升箭头
- 不要一提 AI 就画机器人脑袋
- 不要一提创业就画火箭
- 不要一提商业就画美元符号
- 不要一提连接就画节点网络

这些都太像模板。优先寻找更具体、更物理、更有动作的隐喻。
