# Crayon Doodle Illustrations

## 核心定位

把抽象观点变成一张张“**手写讲义 + 彩铅隐喻画**”的中文知识卡。

默认不是纯插画，也不是把文章原文塞进图片。每一页先提炼一个清楚的判断，再用短手写文案建立认知，用一个具体物理场景把抽象关系画出来。

视觉目标：像一本认真但有趣的创意笔记——暖米白纸、明显彩铅/蜡笔颗粒、橙红和钴蓝、轻微错位、手写字、自然留白、低科技物件、真实动作、一个奇怪但成立的隐喻。

一张合格的图应该让读者：

1. 先读懂一句判断；
2. 再被下方场景吸引；
3. 1-2 秒内理解“为什么这个场景能解释这句话”；
4. 即使离开正文，也能记住这页的核心意思。

## 工作流

### 1. 先消化内容

读用户给的文章、帖子、Markdown、Notion、截图、链接或主题，提炼：

- 这篇内容真正想反驳什么？
- 最重要的新判断是什么？
- 哪些段落承担认知转折？
- 哪些是机制，哪些是例子，哪些是行动建议？
- 什么内容只适合文字，不值得画？

不要平均切段。优先找“认知锚点”：

- 反常识判断
- 前后对比
- 一个关键机制
- 一个商业后果
- 一个边界条件
- 一个具体行动

### 2. 把每页压缩成“单页判断”

每页最多四层：

1. **主标题**：1-3 行，通常 10-24 个中文字；
2. **短解释**：2-6 行，短句；
3. **强调句**：可选 1-2 行，橙红色；
4. **插画内标注**：0-5 个短词。

不要直接复制长段正文。图上文字越多，中文错误概率越高，也越容易变成 PPT。

### 3. 选择画布

用户未指定时：

- 小红书 / 中文知识轮播：默认 `3:4` 竖版；
- Instagram / 通用社媒卡：可用 `4:5`；
- 公众号正文插图：如果正文排版需要，可改 `4:3` 或 `16:9`，但仍保留手写知识卡视觉语言。

同一组轮播的画布比例必须一致。

### 4. 先设计 shot list

如果用户只说“分析怎么配图 / 先规划 / 做 shot list”，先不要生图。

默认输出 5-9 页。每页写清楚：

- 页序
- 核心判断
- 主标题
- 短解释
- 橙红强调句（可选）
- 核心视觉隐喻
- 角色正在做什么
- 主要物件
- 构图方向

整组还要说明：

- 哪页是封面
- 哪页承担认知转折
- 哪页最适合传播截屏
- 是否存在重复构图

### 5. 重新发明视觉隐喻

不要先想“画什么好看”，先把观点转译成物理关系。

步骤：

1. 抽象关系变成物理行为：流动、卡住、漏掉、重复、桥接、筛选、堆积、拆分、接线、交付、续流、回流。
2. 再找低科技物件：水管、河、桥、箱子、桌子、旧机器、插头、工具、秤、门、标签、容器、轨道、绳子、试验台。
3. 让人物或物件真的执行这个动作。
4. 删除不承担概念的装饰。

优先生活化、低科技、具体的场景。不要默认使用漏斗、火箭、拼图、灯泡、靶心、握手、上升箭头等陈旧商业图标。

### 6. 轮播要有叙事推进

默认不是“9 张彼此独立的海报”。

推荐推进：

`封面问题 -> 常见误解 -> 新判断 -> 原因/机制 -> 后果/对比 -> 适用边界 -> 行动`

连续两页不要同构。可以在：

- 大物件隐喻
- 人物互动
- 水流 / 路径
- 前后对比
- 机器 / 装置
- 小群体场景

之间轮换，但背景、色板、手写语言、边距和材质必须保持一致。

### 7. 明确要求生成时直接生图

如果用户明确要求“生成 / 做图 / 画出来 / 输出图片”，不要停在建议阶段。

每页单独生成，不要把多张图先拼成九宫格。

单张提示词至少包含：

- warm ivory / cream paper background
- visible colored-pencil / crayon grain
- handmade Chinese typography
- vermilion-orange + cobalt-blue + graphite palette
- dry imperfect strokes and slightly wobbly outlines
- editorial notebook / handmade explainer feeling
- strong text-above / illustration-below hierarchy
- one physical metaphor per page
- generous quiet negative space
- no platform UI
- no PPT infographic / vector / glossy 3D / tech dashboard

具体模板见 `references/prompt-template.md`。

### 8. 系列一致性

一组图至少固定：

- 同一个暖米白背景
- 同一橙红 / 钴蓝色系
- 相近的标题字号和手写粗细
- 相近的页边距
- 相近的彩铅颗粒密度

但不要固定：

- 每页完全一样的构图
- 每页都出现同一个人物
- 每页都画同一种机器
- 每页都用同一条箭头

**统一的是世界，不是模板。**

### 9. 不要照抄参考截图

用户提供的截图只用于提取通用视觉语法：

- 纸张
- 材质
- 色板
- 信息层级
- 手写感
- 插画与文字的比例
- 隐喻的讲解方式

不要复制其中的：

- 具体人物长相
- 精确服装组合
- 鸡、直升机、桥、机器等独特场景组合
- 原文案
- 精确构图
- 角色动作

同主题也要重新发明物理隐喻。

### 10. 平台 UI 不是画面元素

参考截图中的以下内容属于平台界面，生成时一律禁止：

- `1/9`、`2/9` 等页码胶囊
- 左右切换箭头
- 底部轮播圆点
- App 边框
- 点赞 / 收藏 / 分享按钮
- 导航栏
- 水印

如果模型生成进去，按 `references/editing-recipes.md` 优先局部删除。

### 11. QA + benchmark

生成后先跑 `references/qa-checklist.md`。

重要项目或公开 benchmark 再用 `references/benchmark-rubric.md` 打分：

- 纸张
- 材质
- 色板
- 手写文字
- 隐喻
- 构图
- 人物动作
- 系列一致性
- 中文准确性
- 原创性

低于 16/20 通常不要直接交付。

### 12. 编辑优先级

如果结果已经 70%-80% 正确，不要轻易整张推翻。

按顺序修：

1. 平台 UI 污染
2. 中文标题错字
3. 信息密度 / 构图
4. 材质与色板漂移
5. 人物动作
6. 最后才是小装饰

### 13. 保存交付

如果在 workspace 内工作，把最终图保存到：

```text
assets/<article-slug>-crayon-doodle/
```

按顺序命名：

```text
01-cover.png
02-misconception.png
03-core-insight.png
...
```

不要覆盖已有图片，除非用户明确要求替换。

## 默认视觉角色

可以使用“创客观察者”作为弱重复角色：普通年轻人 / 学生 / 创客，蓝色上衣，可有橙色帽子或橙色工具，比例自然，表情克制，正在实际操作某个东西。

它不是必须出现的 mascot。人物存在的唯一理由是让抽象关系发生动作。

详细规则见 `references/character-language.md`。

## 输出口径

### 只做规划时

短而准地给 shot list，不要长篇解释美术理论。

### 直接生成后

说明：

- 一共生成几页
- 每页表达什么
- 哪页最适合作封面 / 首图
- 哪些图最稳，哪些可选
- 保存路径（如果有）

让图片承担主要表达，不要用很长的文字替图片辩护。
