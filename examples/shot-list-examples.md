# Shot List Examples

下面不是固定模板，而是展示 Skill 应该如何把“文章”压缩成“页面序列”。

---

## 示例 A：产品能跑，不代表产品能卖

### P1 封面

- 核心判断：Demo 能跑，和生意能跑，是两件事。
- 标题：`产品能跑 ≠ 产品能卖`
- 短解释：不解释太多。
- 隐喻：一个人在测试台上把小机器跑起来，机器右侧却没有出口，客户站在远处看。
- 构图：标题占上 30%，下方大机器 + 人。

### P2 误解

- 核心判断：技术人经常先验证“有没有用”。
- 标题：`产品回答：这个功能有没有用？`
- 解释：功能 / 性能 / Demo / 可运行。
- 隐喻：创客拿着一个亮着的小仪器，自己很满意，但桌对面的人没有掏钱包。

### P3 转折

- 核心判断：商业验证问的是“谁会付钱”。
- 标题：`销售回答：谁有预算买？`
- 强调：`谁拍板？怎么交付？`
- 隐喻：一根橙红色电线从产品穿过审批门、预算盒，最后接到付款信封。

### P4 完整产品

- 核心判断：客户买的常常不是裸软件。
- 标题：`国内卖软件，往往不只是卖软件`
- 解释：软件 + 服务 / 定制 / 部署 / 硬件 / 交付。
- 隐喻：电脑程序像机器核心，周围接上工具箱、服务器、包装箱和现场安装。

### P5 收入质量

- 核心判断：一次爆单不等于可重复收入。
- 标题：`不是能收费，而是能持续收钱`
- 解释：一次性卖爆像暴雨；稳定续费像河流。
- 隐喻：一边是短暂暴雨落进桶，一边是稳定水龙头流成河。

### P6 适用场景

- 核心判断：黑客松更适合验证早期 C 端 / 社区型想法。
- 标题：`什么项目适合从黑客松启动？`
- 解释：早期用户 / 社区 / 传播 / 种子用户。
- 隐喻：一小群真正懂产品的人围着一个刚启动的装置测试。

### P7 行动页

- 核心判断：公司注册不是第一步，真实付费才是。
- 标题：`先别急着开公司`
- 解释：先找 10 个真实用户，拿到 3 个真实付费，再谈扩大。
- 隐喻：桌上一个透明罐子里出现前三枚硬币，旁边是三位真实用户。

## 示例 B：AI 没有拉平差距，它把执行变便宜了

### P1

- 标题：`AI 没有拉平差距`
- 强调：`它先把执行变便宜了`
- 隐喻：很多人拿到同样的廉价工具，但只有一人知道该把它接到哪里。

### P2

- 标题：`会生成，不等于会判断`
- 隐喻：机器不断吐出纸张，一个人在纸堆里筛选，另一个只是继续按按钮。

### P3

- 标题：`真正贵的是：知道该做什么`
- 隐喻：巨大的岔路口，工具都在后面，选择方向的人站在最前面。

### P4

- 标题：`Agent 压缩的是重复劳动`
- 隐喻：自动小机器在搬箱子，人站在上方重新设计路径。

### P5

- 标题：`判断力来自真实反馈`
- 隐喻：一个人把想法纸条丢进现实机器，机器另一头只返还“买 / 不买 / 用 / 不用”的硬反馈。

### P6

- 标题：`所以不要只练 Prompt`
- 隐喻：桌上有一支很高级的笔，但真正重要的是旁边被反复修改的实验记录。

### P7

- 标题：`让 AI 替你做更多，让现实反驳你更多`
- 隐喻：人把更多小实验放上跑道，远处有清晰的反馈旗帜。

## Shot list 自检

输出任何新 shot list 前检查：

- 每页是不是一个真正不同的认知动作？
- 标题有没有从原文压缩，而不是直接复制长句？
- 隐喻有没有互相重复？
- 连续两页是否同构？
- 是否至少有一页把观点落到“真实人 / 真实动作”？
- 最后一页是不是具体行动，而不是空总结？
